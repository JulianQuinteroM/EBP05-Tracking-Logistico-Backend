# Cambios que requiere el front para las cinco HU

Este archivo sirve para coordinar con el otro equipo. El ZIP original revisado era una demo. La copia integrada está temporalmente en `frontend/` dentro de este repositorio; **no** se ha mezclado en el GitHub propio del equipo de front. Antes de llevarla a su rama, deben revisar diferencias con cualquier cambio posterior al ZIP.

1. **Nuevo envío (HU001):** reemplazar el `setTimeout` y el ID aleatorio por `POST /api/envios`. Mapear los campos del formulario al contrato y usar la ficha/código real de la respuesta. Solicitar `POST /api/estimaciones` al cambiar servicio o fecha. Mostrar la fecha de **entrega** para Programado: el formulario original decía “Fecha de recolección”. No añadir dirección de origen ni dimensiones aún.
2. **Búsqueda (HU002):** el inicio envía un ID aleatorio a `/envios/info?id=...`, pero la pantalla de información lee `tracking` o `codigo`. Usar el código que digitó la persona y llamar `GET /api/seguimiento/{codigo}`. El ejemplo `LOG-38472915-5` del demo no pasa Luhn; cambiarlo por `LOG-38472915-8` o por un código creado realmente. La pantalla pública debe quitar nombres, dirección completa y origen mostrado en el mockup.
3. **Listado y ficha (HU003):** reemplazar datos precargados/en memoria por `GET /api/envios` y `GET /api/envios/{id}`. Paginar y ordenar en el servidor; para Sprint 1 se ofrecen tamaños 20/50. El botón “Ver detalles” sí existe en el mockup, pero debe abrir la ficha real y no una muestra fija. No dibujar medidas que todavía no existan.
4. **Editar (HU005):** la lista muestra botón y modal demo, pero se requiere formulario con los datos reales de la ficha, `version` y `PUT /api/envios/{id}`. Mostrar “Editar” solo para `PENDIENTE_RECOGIDA`; el demo también lo permite en “Recogido”, contrario al acuerdo. Una edición efectiva queda auditada en backend; `console.info` no es auditoría.
5. **Cancelar (HU004):** cambiar “Eliminar” por “Cancelar”, pedir motivo y confirmación, enviar `POST /api/envios/{id}/cancelacion` con versión actual. Nunca quitar localmente la fila: el envío queda visible como CANCELADO. Solo disponible para `PENDIENTE_RECOGIDA`.
6. **Acceso:** el ZIP no contiene login ni mecanismo para proteger rutas operativas. La API privada usa credencial de operador como mecanismo local temporal. Diseñar con el equipo backend un proxy/sesión segura; la contraseña no puede quedar en `NEXT_PUBLIC_*`, código cliente, localStorage ni una captura de pantalla. Rastreo público no necesita login.

Para HU futuras: filtros por estado/fecha, exportación, reportes y métricas aparecen en mockups pero no forman parte del contrato Sprint 1. No deben confundirse con los cinco criterios comprometidos. El backend tampoco implementa transición `RECOGIDO`, dimensiones verificadas ni una vista privada de cliente; esas pantallas demo no pueden mostrarse como datos reales del sprint.
